## 真实检索评测

评测集在运行结果前冻结，见 `evaluations/retrieval-cases.json`。20 个目的性样例：18 个正例、2 个负例，由 Codex 按已读原文编写，未经人工双盲审校。金标使用来源路径、哈希、标题和原文摘录，未根据检索排名反推。不能把下表解释成真实用户总体准确率。

| 模式 | Recall@5 | MRR@5 | 平均请求时间 | 实际执行/请求 |
|---|---:|---:|---:|---:|
| 关键词 | 77.78% | 0.6204 | 3.33 ms | 20/20 |
| 向量 | 55.56% | 0.4259 | 31.29 ms | 20/20 |
| 混合 | 61.11% | 0.4907 | 7.45 ms | 20/20 |

没有降级冒充向量；索引实为 12,011 × 384。固定模型 revision：`2c4055b12046f11709e9df2c122e59ffbdc2f900`。语料初始化另计 1,125 ms；向量首次查询含模型加载，为 472 ms，其余 19 次均值约 8.09 ms。按模式顺序运行，耗时不是严格公平的性能对比。

三模式的绑定型号结果均为 0/33 错型号；两个负例都只有一个正确返回空。不存在的功能仍可能召回相似词语资料，因此检索不能代替主张核验。向量改善了 Fold 键盘计重、Ultra CPU 版本限定等个别结果排序；混合整体召回下降。本版据此默认关键词，保留 `SEARCH_MODE=vector/hybrid` 实验入口。

完整结果：`evaluations/retrieval-results-2026-10-22.json`。复现：先 `pnpm search:build`，再 `pnpm search:evaluate`。模型和索引在忽略于 Git 的 `output/search-cache/`；重新下载/构建需要时间与磁盘。

## 验证方法

- 自动化测试检查证据引用、修订优先级、型号/系统/重量条件、词法降级和索引热更新、局部修订不新增事实、核验失败暂停交付、HTML 转义和导出边界。
- 浏览器回归使用合成 API 响应，避免把 UI 测试冒充模型验证。覆盖追问暂停自动生成、未提交答案、手动选型跨渠道保留、回答后重理解、接口失败保留输入、手机布局、导出。
- 真实 DeepSeek HTTP 流程独立执行。使用虚构测试客户，保存原始输入、模型输出、审查记录和流式终态；独立复核自动审核通过的内容。不会把参数有据等同于附带收益有据。
- 本地构建及部署包生成单独验证；本机没有 Docker 命令，未执行容器构建或线上部署。

浏览器插件未出现在本会话可用工具中，因此使用 Playwright；视口为桌面 1440×1000 和手机 390×844。后续若要在同一登录浏览器里跟踪操作，可安装 Browser 插件；本次测试不依赖它。

## 仍然存在的限制

模型审核可能误判。程序对因果、比较、体验收益采用保守证据检查，可能让可接受的文案停稿；自动删句后也可能降低连贯性。图像内容未做像素级识别，仍需核对图示和销售配置。软件、价格、库存未接入实测或实时数据。研究标签与候选规则需要更多真实客户样例验证。

向量评测尚小且未人工审校，当前未证明整体优于关键词。改算法应另加未参与调优的留出集，不用本组问题反复调分。多用户隔离和正式部署不在本次本地版本范围。
