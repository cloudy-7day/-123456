# 客户理解标准 v0.3 · 复赛整合版

基于 12 篇小红书需求帖形成，等待门店实际使用反馈。这是理解检查表，不是要求客户逐项填满的问卷。研究维度仅用于后端理解，保留当前有限营销草稿流程；未知信息不补造，不代表商品适配已通过。

| 维度 | 记录什么 | 有相关需求时怎么问 |
|---|---|---|
| 使用场景与任务 | 在哪里用、用来做什么、多久一次。 | 最常在哪些地方用？一次通常要完成什么任务？ |
| 常用软件与系统 | 必需软件、关键版本或插件、本地还是远程。 | 有没有必须安装的软件或插件？在本机运行，还是连接服务器？ |
| 性能与任务负载 | 文件规模、同时开的程序、渲染或计算任务。 | 最复杂的一次任务是什么？大概多大的文件，同时开哪些程序？ |
| 多设备协同 | 已有型号与系统，以及传文件、投屏或扩展屏等具体动作。 | 要和哪台手机、平板协同？主要想完成哪一个动作？ |
| 便携与续航 | 携带频率、含充电器重量、离电时长和插座条件。 | 每天背多久？通常多长时间不能充电？现在的电脑哪里不方便？ |
| 屏幕与输入体验 | 阅读、键盘、触控板与鼠标习惯；有需要再确认屏幕细节。 | 主要看文档还是处理图像？键盘、触控板有没有特别在意的体验？ |
| 接口、外设与网络 | 鼠标、移动硬盘、显示器、投影和联网限制。 | 必须连接哪些外设？能接受转接器吗？ |
| 存储与数据 | 素材或数据大小、已有硬盘、备份和交付。 | 平时要保存哪些资料？是否已有移动硬盘或备份方式？ |
| 预算与购买条件 | 硬上限还是期望区间、配件口径、新机或二手、购买时间。 | 预算是大致期望还是不能超过的总价？包含哪些必要配件？ |
| 使用年限与维护 | 计划用多久、后续需求变化、扩展和维护顾虑。 | 希望用几年？后续课程或工作是否会有明确变化？ |
| 痛点与优先级 | 为什么换机，哪些不能妥协，哪些愿意取舍。 | 如果价格、重量和性能不能同时满足，最不能妥协的是哪一个？ |
| 产品意向 | 区分已选型号、候选型号、已有设备和他人建议。 | 这个型号是已经选定，还是想先了解的候选？ |

## 判断规则

- 已明确：逐字引用输入，只说明客户说过；不等于产品事实已经验证。
- 推断：必须有原文依据和解释，人工确认不会自动把推断升级为事实。
- 待确认：保留未知，不从职业、学校、品牌或“办公”标签补值。
- 每轮最多 2 个问题；同主题合并，仅询问能改变候选或核验路径的信息。已有答案不重复追问，普通未知可稍后补充。知识库无报价时，预算只记录，不能假装完成价格筛选。
- “希望轻便、最好 1kg 左右”是偏好；只有明确“不能超过”才视为硬限制。
- 性能记录具体任务和规模，不直接推算 CPU/GPU/内存；AI、剪辑、办公都要理解真实负载。
- 多设备协同记录具体设备、必要版本和目标动作；同品牌或手机连接成功不代表平板也支持。没有协同需求就不强问系统版本。
- 产品意向区分想了解、候选、已选、已有设备与他人建议；明确提及不代表决定购买。
- 当前目录支持有来源的型号、重量与屏幕信息；多配置、折叠状态、不含键盘等口径保持独立。候选用于营销草稿，不等于兼容性、预算或实际体验已验证。

## 保存与内容生成

未知或冲突不阻塞保存。洞察被编辑后须重新理解，保存结果附带暂停原因。有限草稿围绕有证据的任务与产品事实组织；未核验产品卖点、软件兼容性、价格、活动和参数不可作为承诺。

详细来源与阅读边界见 [调研记录](RESEARCH.md)。

## 决策追问接口

`explainDecision(analysis, catalog, {manualProduct}={})` 返回候选、最多两项决策追问、排除理由和核验限制。只使用本轮有效 fact；修订后重新理解会替换旧依据。已回答的问题不重复追问，不因职业直接补软件、设备或硬件要求。重量和屏幕的明确数值硬限制只在资料足以判断时排除产品，部分配置跨界和未说明数据保持待核验。

研究来源记录是 2026-10-18 的定性样本，恢复来源不表示重新访问过原帖，也不证明任何产品事实。
