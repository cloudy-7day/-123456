# 生成按钮与自动补充修复

问题：编辑洞察后 dirty 状态禁用确认，用户需要回顶部重新理解；软件和本地/远程 AI 方式未知被当作硬性阻断；之后还必须手动选型号并再次勾选，生成按钮一直置灰。

当前行为：

- 填写完整输入后直接点击“生成文案与店员脚本”。
- 点击继续会自动重新理解未合并的修改、保存当前需求、准备资料库候选并开始生成；保留“仅查看理解”入口。
- 软件、预算、已有设备等未知项保留为 warnings 与 draft_limitations，允许有依据的有限草稿。不补造课程软件、远程算力、价格或适配结论。
- 只对相互矛盾的原文、未解决产品意向歧义等给出具体原因。按钮不因未知字段或缺少勾选而永久禁用。
- 无指定型号时从实际目录准备候选，明确标注“未验证适配、可修改”；原始产品意向仍保持 unspecified。有明确意向时尊重该意向，不能确定具体版本则请选一个。
- 后端仍校验分析版本、引用与冲突；修改完整输入会清空旧补充，生成期间锁定上游操作。

## 验证

60 项后端测试通过。浏览器合成回归验证了“编辑洞察 → 直接继续 → 自动重新理解 → 无勾选生成”、单渠道请求、候选选择、复制、导出、输入隔离与手机布局。

真实联调直接使用原校园示例：计算机新生、写代码与 AI、去图书馆、预算 7000—10000、课程软件与学校远程算力未知、未指定型号。未额外填写任何字段，一键完成分析与生成。选用 `MateBook 14 酷睿 Ultra（Windows 系列）` 作为未验证的文案候选；小红书标题“计算机新生选本：图书馆写代码怎么挑”，生成完整文案、店员脚本及 3 张本地资料包配图。最终 `complete=true`、`delivery.status=draft`；复制、导出、图片加载和手机布局通过。

证据在本机忽略目录：`output/assisted-analysis.json`、`assisted-events.json`、`assisted-verification.json`、`自动补充-小红书-文案与店员脚本.txt`。不进入部署包。

页面仍为 `http://127.0.0.1:8791/scenario/`，已重启整合服务；原 8787 与线上魔搭未修改。已打开的旧页面需要刷新才能加载新交互。部署包从同一源码重新生成，仍需另行进行 Docker/线上验证。

复核补充：手动更换候选时不会输入一个字符就自动提交；输入框保持展开，完整输入后点击“按当前候选生成”。候选来源区分 system_candidate / input_match / salesperson_selection，系统候选不会被标记成人工确认选型。相关浏览器与后端回归通过。
