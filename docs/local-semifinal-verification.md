## 实际链路

1. 理解完整输入，提取已知条件、合理推断和未知信息。
2. 按已有候选规则选择完整型号，读取该型号知识库原文与图片。
3. 只读查询 research/semifinal-2026-10-22/research.sqlite，学生命中 SC01、会议命中 SC02，载入情境候选、表达模式和对应产品分类；排除不合格记录。
4. DeepSeek 生成完整结构，再单独润色小红书正文。学生用一份汇报串联寝室、教室、图书馆；会议用一个项目串联会前、会中、会后。
5. 独立模型对最终标题、正文、行动引导和配图说明逐段审阅，产品主张必须给出具体型号的原文摘录。程序检查覆盖完整性、摘录是否真实、引用归属和数值。
6. 未通过时最多自动修订一次：先剔除被否决的句子，再补顺叙事，保留已通过的表达，不重复自由润色。随后重新核验全文。仍未通过则暂停交付，正文及配图不进入复制、导出结果；保留原因供排查。屏幕尺寸与比例前缀会在核验前省略，最终审阅仍针对实际显示的全文。
7. 页面显示完整文案及对应型号图片。研究依据、核验记录和使用条件折叠展示。

研究资料用于选择叙事角度，不能证明产品功能。图片取自本地资料包中的对应型号目录，图片元数据不能作为功能证据。

## 本机启动

要求 Node.js 24。一般环境使用 npm start，按 .env.example 配置已有本地凭证即可。不要复制真实密钥到提交文件。

本机原生 Node 网络请求出现连接重置，本次使用可选 MODEL_HTTP_TRANSPORT=curl，并仅在测试服务进程中沿用本机已启用的 HTTPS 代理。临时启动脚本为 tmp/start-semifinal.ps1，无密钥内容。没有修改全局代理配置。curl 仍校验 TLS、不跟随重定向，认证通过标准输入传入，不写命令行参数。

## 能力边界

- 核验是模型辅助原文核验及确定性检查，未执行人工事实认证、图片像素内容核验或完整营销合规审核。
- 两类场景是演示候选，不代表已证明华为购买人群中的职业规模排名。
- 分类中的 SKU 售价缺口尚未补齐，本轮不宣称精确预算选型或实时商城价格。
- 朋友圈、竞品横向对比和店员后续跟进指南未在本轮接入。
- 服务保留已有单任务运行限制，连续生成应等待前一任务完成；模型调用失败会明确报错，不使用伪造结果代替。

## 本轮体验与失败排查补充

- 首屏未操作时停留 3000ms 后引导到输入；参考 `D:/111 codex/motion-core.js` 与 `app.js` 的 1150ms、smoothstep 缓动。鼠标滚轮、触摸、点击、键盘或输入取消首次引导；动画过程中也可主动打断。系统偏好减少动态效果时直接定位。
- 单独查看理解、进入产品与生成卡、返回结果或发生错误时定位对应卡片。计时、进度与复制状态更新不重复拉动页面；编辑原输入不跳回旧理解卡。
- `tests/browser/guided-scroll.mjs` 覆盖三秒延迟、主动操作取消、减少动画、手动入口、运动中断及手机布局；`focused-flow.mjs` 覆盖阶段定位、错误定位、保留输入、重试和原有交互。均通过隔离 Chrome 验证。
- 68 张本地原图建立 SHA 绑定的离线双指纹索引；检索时与最终配图计划均筛查文件重复、视觉近似、同角度不同配色、跨型号。不同画面不足时提示缺图。未知角度只声明指纹筛查局限，不保证任意图片均能准确分角度。
- 两组新示例各保留键盘俯视、侧面、斜向外观三张图；页面新增折叠的配图筛选记录。`output/semifinal-image-review.png` 已目视确认三张画面不同。该复查不证明图片中的产品功能或具体销售 SKU。
- 用户最初那次错误没有保存，无法倒推出准确根因。本轮修复已复现的无效 JSON 中断：仅对正常结束但 JSON 无法解析的模型响应重试一次；认证错误不重试，截断输出不冒充完整结果。
- 本轮另一次真实生成被事实核验阻止。发现文风修订意见没有句子编号，无法由既有修订步骤准确移除参数句；已改为逐句反馈，并以先失败、后通过的回归测试验证。失败事件保存在 `output/semifinal-student-blocked-review-events.json`，没有用成功样例覆盖该记录。
- 新增最近 20 次分析/生成诊断记录，包含编号、阶段、受控错误分类及核验轮数，不记录完整客户输入、模型原文或密钥。最终错误消息保留诊断编号；接口为 `/api/run-diagnostics`，文件为 `output/run-diagnostics.json`。事实核验仍是模型辅助，不应把某次通过理解为人工确认全部主张。

## 场景卡核对

原始参赛手册第 5 页的任务输入要求是“输入产品、目标人群、场景和发布渠道”；场景理解还要求提取“购买阶段、主要问题和内容目标”。未规定按职业分类，也未给出可据此复原的官方场景卡模板。现场照片提到随机指定场景卡与产品，不足以证明卡片等同职业标签。

因此学生、医生、律师可以作为人群入口；学生的小组汇报、职场的项目会议是具体任务候选。一张完整任务卡应涵盖产品/人群/任务处境/主要问题/购买阶段（未知可保留）/内容目标/平台。寝室、教室、图书馆属于同一业务任务下的地点切片，不能自动当作三类业务场景。现有“学生学习”和“职场会议”是可编辑演示入口，不宣称官方卡片原文。
