# 文案生成与三组本地成果验收

本轮完成学生小红书、职场会议小红书、职场会议朋友圈三组真实运行，覆盖开学季和职场办公两个业务场景、两个平台。完整结果、图源与逐句核验记录在 `output/acceptance-summary.md` 和对应 JSON 内。仅本地更新，未推送线上。

## 原因与修复

1. 旧流程只查事实与结构，局部修订会把邻句复制回来。增加发布文案检查：正文与结尾的重复、朋友圈篇幅与单卖点、小红书分段、参数、核验说明。事实通过不能绕过文案检查。
2. 事实修订与整篇文风修订分流。需要整篇调整时，从原始需求与产品事实重新组织，不反复沿用已否决草稿。局部修订只处理问题句，所有改动仍进入独立事实核验；未改变的句子仅在同一原文、同一使用条件下复用核验记录。
3. 核验模型漏回部分句子时，先补审遗漏句子一次，不能因此直接通过，也不把漏审当作用户需要修改内容的理由。覆盖、引用、连续原文摘录、数值和必要限定校验继续保留。
4. 编辑与局部修订启用同一 DeepSeek 模型的思考模式。依据：[DeepSeek 官方接口文档](https://api-docs.deepseek.com/guides/thinking_mode/)。不展示或保存模型内部推理，只使用最终 JSON；页面分析卡仍展示提取摘要和实际任务进度。
5. 知识库产品图片不承担功能证明，生成中的图片说明统一为产品资料配图；保留图片原始索引名称与来源。没有照片就不编造现场图。

## 场景卖点多样性（本地增补）

- 根因：润色阶段存在“找到产品事实页后只使用该页”的过滤，遗漏同型号《卖点与限制》中的功能和必要条件，导致重复讲触控和键盘。现在保留检索返回的产品文字证据，继续排除图片索引、参考文案和卖点转译；知识库逐句核验流程不变。
- 小红书按“场景任务 → 具体麻烦 → 一项主要有据功能”组织。后续场景不再顺带复述前文功能；没有独特证据的段落缩短，必要重复允许，不强凑三个卖点。
- 跨设备传送只在本型号文字证据支持时采用，保留支持设备、同账号等范围条件；不把“生态”泛化成任意手机互通，也不假定客户已有设备。朋友圈仍只保留一个核心卖点。
- 新增回归测试确认规格页和功能限制资料同时传入润色且原文条件完整保留，不使用配图说明证明能力。

## 展示样式

保留生活笔记风格与连续任务叙事。场景 emoji 在标题中放大至桌面 32px、手机 28px；长段落开头的简短场景提示可独立呈现。桌面配图宽度 300px、高度 160px，手机 240px/140px，保持比例，以正文为主。

发布显示、复制和导出使用同一格式层：隐藏引用标记、汇总并去重已有话题标签。原始成稿与核验记录保持不变，不通过显示层篡改产品主张。

## 验证

- 200 项自动测试通过（含场景卖点增补回归）；前轮构建成功，本次仅修改服务端润色规则。
- 两篇小红书和一篇朋友圈完成真实输入理解、确认、选型、检索、生成、核验、展示。
- 学生选择 MateBook 14（鸿蒙版）；职场会议选择 MateBook D 16 SE 版（Windows 系列），选型由不同需求产生。
- 三组保存成果分别通过桌面/手机显示、emoji 尺寸、小图尺寸、复制、导出一致性检查。
- `node scripts/verify-semifinal-results.mjs` 校验三组数据和覆盖范围，生成验收汇总。

本轮真实结果通过并不保证后续每次模型生成都通过；无法核实的产品主张仍会拦截。上述验收不是官方评审结论。复赛说明书、录屏与线上发布不属于本次本地修复范围。
