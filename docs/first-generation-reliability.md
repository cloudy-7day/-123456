# 首次生成失败排查与修复

日期：2026-10-22。本轮仅修改本地 8792，未推送线上。

用户截图属于知识库核验暂停，不是打开页面的 HTTP 错误。旧实现只保留最新整轮输出，后续测试会覆盖此前失败正文，因此不能将某份历史结果冒认为截图的完整记录。连续新浏览器会话实测复现并保留了以下问题：

1. 小写引用 `[s1]` 未被识别为引用，其数字被当作产品数值，产生假阳性。
2. “手写笔支持情况需确认”等纯未知说明被关键词规则误判为功能承诺。
3. 输入理解将事实概括为另一种措辞，与引文不完全相同，严格校验因此停止。现改为在且仅在单一引文真实存在时显示该原文，丢弃模型改写；伪造引文仍拒绝。
4. 全篇修订会改动已通过句子，重新审阅未变化文本也可能出现不一致判定。
5. “整机外观”触发了“整机”功能关键词；同时局部修订可能把不成立的手写笔描述改成另一个功能推断，浪费修订机会。
6. 同型号省略 HUAWEI 品牌前缀时，型号中的 14 被当成规格数值；“3:2 OLED 抗反射触控屏”中的修饰词未被屏幕参数清理识别。

## 最终行为

- 引用格式统一大小写，未知来源编号仍拦截；不删除真实产品数字来规避核验。
- 型号数值检查识别当前型号的品牌省略形式，仍保留版本区别；正文其他真实参数照常核验。屏幕比例前缀可省略，OLED、抗反射、触控等剩余主张仍接受完整原文核验。
- 纯待确认说明与正向功能承诺分开判断；一句中追加“但支持所有软件”等承诺仍需证据。
- 纯整机外观标签不属于功能承诺；同句出现触控、性能等主张仍核验。未通过的配图说明统一收窄为“产品外观图”，保留实际素材引用与未出错的说明，不再让模型从照片推导另一项功能。
- 局部修订只能提交指定问题句的替换，不能改变其他正文、条件或客户输入。最多两次局部修订，每次修改都重新核验。
- 只在同次请求、同批资料、同一位置、完全相同句子及相同使用条件下沿用已通过结论；覆盖、引文和数值检查每次仍执行。没有跨客户或跨请求缓存结论。
- 真正缺少证据仍暂停交付。红色区域只展示阻塞的问题句，普通未知项不作为阻塞理由堆砌。
- 最近 10 次失败核验详情保存至 `output/failed-reviews/<诊断编号>.json`，避免后续成功覆盖。文件保留问题句及核验记录，不含 API 配置；不随部署上传。

## 验证方法

回归测试覆盖局部修改权限、引用保留、条件变化导致重新核验、假引用拒绝、未知说明与正向承诺区分、原话回填和失败历史保留。

前三组实测分别使用学生、会议、学生、会议四个全新浏览器进程；每次只点击一次生成，自动修订属于同次请求。首轮序列 1 次通过、3 次失败，日志为 `tmp/first-open-*.log`；中间修复序列 3 次通过、1 次失败，日志为 `tmp/fixed-first-open-*.log`，由此发现配图描述问题；第三组 3 次通过、1 次失败，日志为 `tmp/final-first-open-*.log`，由此发现型号简称与屏幕修饰词问题。没有将失败后的重试记为成功。

最新代码另以学生、会议两个全新浏览器会话验收，日志为 `tmp/verified-first-open-{student,meeting}.log`，成功结果为 `output/verified-first-open-{student,meeting}.json`。

验收结果：2/2 首次点击完成，未手动重试。学生经过初审与两次局部修订核验通过，会议经过初审与一次局部修订核验通过；两者均验证完整文案、图片加载、复制、导出及移动端无横向溢出。修订发生在同一次生成请求内。

完整 Node 回归测试 160 项通过；浏览器交互回归通过（模拟接口，仅验证交互，不计入真实生成成功次数）。页面两组已核验示例、图片、复制导出与移动端显示已验证。

模型辅助核验仍不是人工认证；有限次数通过不保证任意输入永不失败。网络或真实资料不足仍会明确报错，不以旧成功内容替代新请求。
