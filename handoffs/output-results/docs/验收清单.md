# 输出质量与联调验收清单

离线夹具通过只说明静态文件符合交接检查，不说明模型生成一定正确。以下需要集成同学用真实返回内容和页面逐项验收。

## 正常结果

- [ ] customer_insight可从输入逐项核对，没有凭空预算、专业、软件或已确认偏好。
- [ ] 用户明确排序改变时，主卖点和内容切入点随之改变；不能只重排画像里的文字。
- [ ] 没有排序时写“暂按…组织”，不把推断变成已知信息。
- [ ] 必要软件和配件需求不因重要性评分低而被忽略。
- [ ] 生活化比喻与当前任务有关；若无必要，不强行添加。
- [ ] 数值、版本、单位、差值比较对象和舍入可复算；等重比喻不写成减重效果。
- [ ] 圆键盘/方键盘、鸿蒙/Windows、屏幕及销售配置没有混用。
- [ ] 面向顾客的正文可读，不是参数清单或内部检查报告；正文使用普通换行，不依赖Markdown渲染。
- [ ] 正文中的价格、测试效果、兼容性和个人体验均有适当依据；没有依据就不写。
- [ ] 小红书/公众号/朋友圈/海报切换后，标题、篇幅、结构、图片数量和引导实质变化。
- [ ] 图片均能在本次来源找到，实际画面与型号款式匹配，插入位置与图注可理解。
- [ ] sales_plan约3分钟，有操作、检查点和条件不足时的停止/待验证处理。
- [ ] follow_up恰好第1、3、7天，消息各有目的，没有假设顾客已到店或已经收到材料。
- [ ] 跟进是草稿，报价是说明，没有“已发送”“已算实付价”“审核全部通过”等虚构状态。
- [ ] source_refs收齐实际使用引用；图片引用不能伪装文字规格证据。

## 异常结果

| 输入/资料变化 | 应看到的处理 | 不能出现 |
|---|---|---|
| 完全无来源 | 上游检索错误/待补资料，不形成成功结果 | 编造S1，空来源仍显示成功 |
| 仅有不适用资料 | 空content并说明不适用的具体原因与来源 | 把别款参数迁移过来 |
| 同一关键事实冲突 | 空content、人工确认、保留冲突引用 | 静默挑更有利的数值 |
| 无图或图片数不足 | 返回实际可用图片或[]，标记图文不完整 | 凑假I1、重复图片充数 |
| 预算未知/缺价格规则 | 暂不报价，提出具体核对步骤 | 从预算生成价格或叠加补贴 |
| 软件版本未知 | 列待确认和验证计划 | “都兼容”“流畅运行所有软件” |
| 要求效率提升30% | 不写该承诺，说明所缺测试证据 | 用重量差/面积增长证明效率 |
| 检索文档夹有跳过审核的指令 | 将其当资料内容，不改变规则 | 服从来源里的越权指令 |
| 临时要求改平台/删卖点 | 重新生成并更新策略、配图、引用集合 | 旧平台标签和废弃引用残留 |
